# UI/UX, Security, DPDP and Future-Readiness Audit, November 2026

Date: 2026-11-06. Branch: `ux-and-audit-2026-11`, from `main` at 2760291. Findings are
numbered `AUD-11/n`. To repeat this audit, follow [`../AUDIT_PLAYBOOK.md`](../AUDIT_PLAYBOOK.md).

This is an engineering review, not legal advice or a penetration test. Nothing in production
was accessed or changed.

## Result

- **One blocker found and fixed:** electricians could not attach the proof photo, so they
  could not resolve a ticket from the app. This is live until the branch is released.
- **Thirteen defects fixed from the UX pass, three from the audit** (BUG-0061 to BUG-0076).
- **No tenant-isolation or injection defect found.**
- **Twelve items remain open,** of which four need a lawyer or an owner decision before
  residents' data is taken at scale.

## How it was checked

| Area | Method |
|---|---|
| UI/UX | 41 pages rendered on desktop and phone, with axe, before and after. Pages reviewed by role, then changed from a written plan |
| Tenant isolation | All 222 Prisma calls without `orgId` in their `where` were listed. Those that use a built-up `where` or a bare `id` were sampled, and each sampled mutation followed a scoped check |
| Injection | Raw SQL (tagged templates only), CSV guards on all four exports, escaping scan of all pages, AI reply rendering, email escaping |
| Authentication | JWT algorithm and expiry, token invalidation, reset tokens, bcrypt cost, public token entropy |
| Client IP | Caddy sets `X-Forwarded-For` itself, and `docker-compose.yml` publishes no API port, so a client cannot spoof it. Not confirmed on the host |
| Dependencies | `npm audit --omit=dev`: 6 moderate or low advisories, fixed by upgrading. Now 0 |
| DPDP | Personal data inventory from the schema; notice compared with the code; requirements register |

**Coverage limits.** This was one pass by one reviewer, with sampling. The thirteen-dimension
multi-agent audit designed for this work stopped at a usage limit, so it did not run. It is
saved for repeat use. There was no live penetration test, and no access to the production
host, so backups, log retention, disk encryption and the server's firewall were not verified.

## UX changes

Applied across the field, resident, sign-in and main admin pages:

- **Accessibility, measured with axe on all 84 page and viewport renders on Windows:** colour
  contrast 105 to 9, links identified only by colour 8 to 0, scrollable regions without keyboard
  access 6 to 5. CI measures on Linux, so its counts can differ. The nine that remain are on
  admin Analytics, Locations and Failures.
- **The field app** has a fixed bottom navigation with the same links on every page, 48px
  targets, a Bright screen option, plain status names, and photos shrunk before upload on a
  weak signal.
- **Residents** get a form that works by keyboard and screen reader, a useful confirmation, and
  a clear review page.
- **Admins** get a first-run guide, the PIN step when adding an electrician, a location screen
  for supervisors, safer parent selection, and QR printing that waits until every sticker is
  ready.
- **Everyone** gets errors that appear on screen in plain words, and failed loads that are not
  shown as empty lists.

**Not done from the UX plan.** These are polish, and none blocks use:

- Consistent phone layouts for the remaining admin tables, and tabbed form validation.
- Admin Assets, Failures, Alerts, AI and Predictions: headers, tab semantics, labels.
- The super-admin dashboard's row menu and shared topbar.
- Dashboard reordering, and `custom-select.js` keyboard improvements.
- Plain status names on the admin Tickets and Dashboard pages, which still show `IN PROGRESS`
  and `OPEN` where the field app says In progress and New.

## Open items

### Needs a lawyer or an owner decision

| ID | Item | Recommendation |
|---|---|---|
| AUD-11/01 | **Who is the Data Fiduciary.** Each hostel decides why residents' and staff data is processed, so Kodspot is probably a Data Processor. No processor contract is in the repository | Have counsel confirm, then sign a short data processing agreement with each organization |
| AUD-11/02 | **Aadhaar.** Nothing needs the number, and the Aadhaar Act limits its collection. The staff migration has not been run | Remove the field. If it stays, take a verified backup and run `scripts/migrate-user-pii.js` |
| AUD-11/03 | **Legal basis wording.** The notice says admins consent on behalf of staff. Consent cannot be given that way; s.7(i) employment use is the likely basis | Counsel to reword sections 3 and 8 |
| AUD-11/04 | **Children.** The notice says the service is not for under-18s, but hostel residents can be 17. The Act requires verifiable parental consent, and reported exemptions cover some educational institutions | Before opening to a hostel with minors, have counsel decide. The simplest safe design is that minors report with no name or phone |
